STTNet Getting Started and API Reference

A lightweight, direct C++17 networking framework for Linux servers

STTNet is built on epoll and the Reactor event-driven model. It provides TCP, UDP, HTTP/1.1, WebSocket, TLS, HTTPS, and WSS support while keeping application code centered on clear callbacks.

It is suitable for lightweight API services, real-time communication, gateways, IoT access, game backends, and networking components embedded in existing C++ applications.

Lightweight and embeddable

The core targets C++17, exposes a compact interface through sttnet.h, and can be installed with CMake or added directly to an existing project.

High-concurrency I/O

epoll, non-blocking I/O, and a one-loop-per-thread Reactor design are combined with multiple event loops, WorkerPool dispatch, bounded send queues, and backpressure.

Practical protocol support

TCP, UDP, HTTP, WebSocket, and encrypted variants are available alongside JSON, logging, file, signal, and common server-side utilities.

Performance note: an older build recorded about 65,000 requests per second with 2–3 ms average latency on a 4-core/4GB development board. This is a historical case, not a fixed result for every machine or the current release. Benchmark the target Linux environment for meaningful numbers.

Getting Started

The following Ubuntu / Debian commands take you from a clean checkout to a running HTTP server.

1. Install dependencies

sudo apt-get update
sudo apt-get install -y build-essential cmake pkg-config libjsoncpp-dev libssl-dev

2. Download and build

git clone https://github.com/StephenTaam/STTNet.git
cd STTNet
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DSTTNET_BUILD_EXAMPLE=ON \
  -DSTTNET_BUILD_TESTS=OFF \
  -DSTTNET_BUILD_BENCHMARK=OFF
cmake --build build --parallel

3. Run the example

./build/examples/sttnet_http_hello

When the server reports that it is listening, use another terminal:

curl -i http://127.0.0.1:8080/ping

A pong response confirms that the server is running. Press Ctrl-C for graceful shutdown.

Use STTNet in your own CMake project

When the source is vendored into your project:

set(STTNET_BUILD_EXAMPLE OFF CACHE BOOL "" FORCE)
set(STTNET_BUILD_TESTS OFF CACHE BOOL "" FORCE)
add_subdirectory(third_party/STTNet)

target_link_libraries(my_server PRIVATE STTNet::sttnet)

For a system-installed package:

find_package(STTNet 0.7 CONFIG REQUIRED)
target_link_libraries(my_server PRIVATE STTNet::sttnet)

Application code includes the public header:

#include <sttnet.h>

Minimal HTTP Server

This program registers /ping and returns pong:

#include <sttnet.h>

using namespace stt::network;
using stt::system::ServerSetting;

int main()
{
    if (!ServerSetting::blockTerminationSignals())
        return 1;

    HttpServer server;

    server.setFunction("/ping",
        [](HttpServerFDHandler &client,
           HttpRequestInformation &request) {
            (void)request;
            return client.sendText("pong") ? 1 : -2;
        });

    if (!server.startListen(8080))
        return 2;

    ServerSetting::waitForTerminationSignal();
    return server.close() ? 0 : 3;
}

After compiling and starting the program, open http://127.0.0.1:8080/ping or use:

curl http://127.0.0.1:8080/ping

Read a request and return JSON

server.setFunction("/user",
    [](HttpServerFDHandler &client,
       HttpRequestInformation &request) {
        auto contentType = request.headerValue("content-type");
        auto body = request.bodyView();

        Json::Value result;
        result["ok"] = true;
        result["content_type"] = contentType;
        result["body_size"] = static_cast<Json::UInt64>(body.size());

        return client.sendJson(result) ? 1 : -2;
    });

Minimal WebSocket Echo Server

#include <sttnet.h>

using namespace stt::network;
using stt::system::ServerSetting;

int main()
{
    if (!ServerSetting::blockTerminationSignals())
        return 1;

    WebSocketServer server;

    server.setGlobalSolveFunction(
        [](WebSocketServerFDHandler &client,
           WebSocketFDInformation &message) {
            return client.sendMessage(message.message);
        });

    if (!server.startListen(5050))
        return 2;

    ServerSetting::waitForTerminationSignal();
    return server.close() ? 0 : 3;
}

A client connected to ws://127.0.0.1:5050 receives each text message back unchanged. HTTPS and WSS can load a certificate and private key through the server TLS configuration API.

Concurrency and production settings

Reactor threads handle network I/O. Expensive application work can be dispatched to a WorkerPool so it does not block an event loop. A bounded pending-write limit provides backpressure for slow clients and prevents unbounded send queues.

ServerSocketOptions options;
options.tcp_no_delay = true;
options.keep_alive = true;
options.listen_backlog = 4096;

server.setSocketOptions(options);
server.setMaxPendingWriteBytes(4 * 1024 * 1024);
server.setGracefulShutdownTimeout(5000);

// HTTPS / WSS
// server.setTLS("server.crt", "server.key");
Signal handling: call blockTerminationSignals() before Reactor or Worker threads are created. A normal shutdown can wait for in-flight requests and pending writes; SIGKILL cannot be caught and therefore cannot trigger graceful shutdown.
