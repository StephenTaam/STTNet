第 17 章：Linux 信号与优雅退出

标出 Linux 信号名称和常见编号，并把异步信号处理与安全资源清理彻底分开。

1. 为什么使用同步等待

异步 signal handler 中只能调用极少数 async-signal-safe 函数。C++ 析构、锁、日志、内存分配和 OpenSSL 清理都不安全。推荐在线程创建前屏蔽退出信号，再由主线程通过 sigwait 模型同步等待。

2. Linux 常见信号编号

信号Linux 编号含义与处理
SIGHUP1终端断开/常用于请求重载；STTNet 不自动处理
SIGINT2Ctrl-C；waitForTerminationSignal() 会等待
SIGQUIT3退出并可能生成 core；不作为正常退出信号
SIGABRT6abort()；保留默认致命行为
SIGKILL9强制终止，不能捕获、阻塞或清理
SIGSEGV11非法内存访问；保留默认行为与 core dump
SIGPIPE13写入已关闭管道/socket；setExceptionHandling() 忽略
SIGTERM15标准终止请求；waitForTerminationSignal() 会等待
SIGCHLD17子进程状态变化；进程管理代码会涉及
SIGSTOP19强制暂停，不能捕获
编号说明：以上是 STTNet 支持目标 Linux 上的常见编号。代码中始终使用 SIGTERM 等符号常量，不要硬编码数字。

3. 完整退出模型

using stt::system::ServerSetting;

// 先设置 SIGPIPE 与致命信号的安全默认行为。
ServerSetting::setExceptionHandling();

// 必须在线程创建前屏蔽 SIGINT (2) 与 SIGTERM (15)。
if(!ServerSetting::blockTerminationSignals())
    return 1;

stt::network::HttpServer server;
server.setGracefulShutdownTimeout(5000);
if(!server.startListen(8083))
    return 2;

// 主线程在正常 C++ 上下文中同步等待退出请求。
const int signalNumber = ServerSetting::waitForTerminationSignal();
if(signalNumber < 0)
    return 3;

// close() 停止 accept，等待在途任务和发送队列，再释放资源。
return server.close() ? 0 : 4;

4. SIGTERM 与 SIGKILL 的区别

SIGTERM (15) 是“请退出”，服务可以停止接收新连接、完成在途请求、刷新日志后退出；SIGKILL (9) 是内核立即终止，没有析构、日志刷新或 finally。进程守护应先发 SIGTERM，超时后才使用 SIGKILL。

5. 正确顺序

  1. 主线程调用 setExceptionHandling() 和 blockTerminationSignals()。
  2. 创建日志、Server、Reactor 和 Worker。
  3. 启动监听。
  4. 主线程调用 waitForTerminationSignal()。
  5. 收到 SIGINT 或 SIGTERM 后调用 server.close()。
不要在异步 signal handler 里 delete Server、写日志或加锁。这类代码可能死锁、重复析构或破坏堆状态。
