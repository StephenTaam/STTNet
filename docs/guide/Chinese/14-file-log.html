第 14 章：文件与异步日志

从简单文件操作到线程安全内存事务，再到有界异步日志队列。

1. 三层文件能力

类职责注意
FileTool创建目录/文件、复制、获取大小适合一次性路径操作
File线程安全文本/二进制读写、内存事务操作前必须 openFile()
LogFile有界队列 + 独立线程异步写日志队列满时丢日志，不阻塞业务线程

2. 普通文本文件

stt::file::File config;
if(!config.openFile("runtime/app.conf"))
    return 1;

config.deleteAll();
config.appendLine("port=8080");
config.appendLine("workers=4");

std::string content;
config.readAll(content);
config.closeFile();

带 C 后缀的方法（例如 appendLineC）用于已经调用 lockMemory() 的内存事务；普通方法会把读取、修改、保存合在一次调用里。复杂批量修改时才使用 lockMemory()/unlockMemory()，并保证由同一线程解锁。

3. 异步日志

// 容量必须是 2 的幂。队列越大，能吸收的短时日志突发越多。
stt::file::LogFile log(16384);
if(!log.openFile("logs/server.log", "yyyy-mm-ddThh:mi:ss.sss", "  "))
    return 1;

log.writeLog("server started");
log.writeLog("client connected");

// 过载时不会阻塞 Reactor，可通过该指标发现日志丢弃。
std::cout << log.getDroppedLogCount() << std::endl;

4. 生命周期与性能

  • LogFile 必须比所有写日志的线程活得更久。
  • 不要在每次请求里打开/关闭日志文件。
  • 热路径日志应控制级别与内容，避免格式化本身成为瓶颈。
  • 日志中不要记录密码、Token、完整 Cookie、私钥或敏感请求体。
  • 进程异常崩溃时，队列中尚未落盘的日志可能丢失；关键审计记录需要独立可靠通道。
