第 6 章：WorkerPool

安全地执行阻塞任务，理解请求快照、响应队列、过载拒绝和退出边界。

1. 哪些任务应该进入 WorkerPool

  • 数据库和缓存客户端调用
  • 文件系统、压缩、图片处理
  • 外部 HTTP/RPC 请求
  • 会睡眠或等待不可预测锁的代码

2. 完整 Demo

#include <sttnet.h>

#include <chrono>
#include <iostream>
#include <thread>

int main()
{
    using namespace stt::network;
    using stt::system::ServerSetting;

    if(!ServerSetting::blockTerminationSignals())
    {
        std::cerr << "failed to block termination signals\n";
        return 1;
    }

    HttpServer server;

    // 限制等待中的 Worker 任务数；达到上限时，
    // STTNet 拒绝新任务，而不是让内存无限增长。
    server.setMaxPendingWorkerTasks(4096);

    server.setFunction("/slow",
        [&server](HttpServerFDHandler &client,
                  HttpRequestInformation &request) {
            // Reactor 回调必须尽快返回。数据库调用、
            // 文件访问、RPC、sleep 和不可预测的锁等待
            // 应放进 WorkerPool，不能阻塞网络事件循环。
            server.putTask(
                [](HttpServerFDHandler &workerClient,
                   HttpRequestInformation &workerRequest) {
                    // client/request 是 STTNet 提供的安全快照。
                    // 不要在这里捕获外层回调局部变量的引用。
                    std::this_thread::sleep_for(std::chrono::milliseconds(200));

                    const std::string result =
                        "worker finished for " + workerRequest.loc;

                    // 服务端 Worker 中，sendText() 会把响应交给
                    // Reactor；Worker 不直接写 socket/TLS。
                    return workerClient.sendText(result) ? 1 : -2;
                },
                client,
                request);

            // 0 means: this processing stage continues in the WorkerPool.
            // 任务返回 1 后，STTNet 会继续执行下一个已注册阶段。
            return 0;
        });

    // 第二个参数是 WorkerPool 线程数，不是 Reactor 数量。
    // 一个 Server 实例使用一个 Reactor 线程推进网络事件。
    if(!server.startListen(8082, 4))
    {
        std::cerr << "failed to listen on port 8082\n";
        return 2;
    }

    std::cout << "WorkerPool demo listening on http://127.0.0.1:8082\n";
    ServerSetting::waitForTerminationSignal();
    return server.close() ? 0 : 3;
}

3. 不要捕获外层引用

// 错误：Worker 执行时，外层回调早已返回，引用可能失效。
server.putTask([&client, &request] { /* ... */ }, client, request);

// 正确：使用 STTNet 传给 Worker lambda 的安全快照参数。
server.putTask([](HttpServerFDHandler &workerClient,
                  HttpRequestInformation &workerRequest) {
    /* ... */
    return workerClient.sendText("done") ? 1 : -2;
}, client, request);

4. 背压和超时

setMaxPendingWorkerTasks() 限制等待任务数。队列过载时框架会拒绝新任务并增加 worker_task_rejections，而不是无限占用内存。

优雅退出不能安全“杀死”已经开始执行的用户任务。数据库、RPC、文件和锁等待必须各自设置有限超时，并保证最终返回。

5. 验证

./build/examples/sttnet_worker_pool
curl -i http://127.0.0.1:8082/slow
预期：约 200 ms 后返回 worker finished for /slow，服务仍能同时处理其他连接。
