第 20 章：项目接入与上线检查

把能运行的 Demo 变成边界清楚、可观测、能安全退出并便于回滚的生产服务。

1. 构建与依赖

生产工程应通过 CMake 目标 STTNet::sttnet 接入，不要复制单个源文件。使用 Release 构建，同时保留独立的 Debug/ASan 构建用于回归。

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
  • 确认 JsonCpp、OpenSSL、pthread 等运行环境依赖可用。
  • 证书、私钥、日志目录和配置文件不要写死为开发机路径。
  • 升级 STTNet 前先运行协议互操作测试和业务回归测试。

2. 网络与系统资源

框架构造参数只是框架容量，不会自动修改 Linux 系统限制。上线前至少核对：

项目要检查的内容
文件描述符ulimit -n、systemd LimitNOFILE 与预期连接数
监听队列listen_backlog 与内核 somaxconn
发送背压每连接待发送字节、单轮写预算和慢客户端策略
WorkerPool线程数、待执行任务上限、数据库/RPC 自身超时
HTTP 输入Header、Body、上传和业务字段的大小限制
TLS证书有效期、私钥权限、协议版本和 mTLS 策略

相关章节：系统初始化与服务端设置、连接安全与输入边界。

3. 数据、日志与秘密信息

  • JSON 解析失败必须返回明确的 4xx，不能继续读取不存在的字段。
  • 异步日志队列要监控丢弃数量，并确保退出前日志对象仍然存活。
  • 密码、Token、Cookie、私钥和完整请求体默认不应写入日志。
  • Base64 只是编码；SHA-1 和 AES-CBC 的使用边界见数据工具章节。
  • 所有外部输入都要先做长度、格式和权限检查，再进入 Worker 或业务层。

相关章节：JSON、文件与日志、编码与加密工具。

4. 进程生命周期

  1. 在线程创建前屏蔽 SIGINT (2) 与 SIGTERM (15)。
  2. 创建日志、Server、Reactor 和 Worker。
  3. 启动监听并公开健康检查/指标。
  4. 收到终止信号后停止接收新连接，等待在途任务和发送队列。
  5. 在超时内完成正常关闭；外部守护程序最后才使用 SIGKILL (9)。

Process 提供进程拉起与重启，不等于完整 Unix daemonize。生产环境优先使用 systemd、容器编排或专用进程监督器。相关章节：Linux 信号、进程监督与心跳。

5. 上线前检查表

发布原则：先压测最慢的真实业务路径，再看框架空响应 QPS。生产容量由业务逻辑、下游依赖和尾延迟决定。
