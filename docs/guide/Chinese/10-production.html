第 14 章：项目接入与上线检查

把示例代码变成可维护、可观测、能安全退出的生产服务。

1. 项目接入

add_subdirectory(third_party/STTNet)
add_executable(app src/main.cpp)
target_link_libraries(app PRIVATE STTNet::sttnet)

2. 推荐目录

app/
├── CMakeLists.txt
├── src/
│   ├── main.cpp          # 进程生命周期与 Server 构造
│   ├── routes.cpp        # 路由注册
│   ├── handlers.cpp      # 业务处理
│   └── shutdown.cpp      # 信号和控制线程
├── config/
└── third_party/STTNet/

3. 上线检查

  • 所有依赖、编译器和 C++17 ABI 已确认。
  • ulimit -n、systemd LimitNOFILE 和容器限制与 maxFD 匹配。
  • 每个数据库、RPC、文件和锁等待都有有限超时。
  • Worker 和发送队列都有上限，并监控 rejection/overflow 指标。
  • TLS 证书覆盖实际域名，私钥权限最小化，客户端校验未被关闭。
  • SIGTERM 能走完优雅退出；超时后也能收敛。
  • 安全限流参数按真实业务调整，并区分压测环境。
  • 日志不会无限增长，敏感数据不会写入日志。
  • 健康检查不执行昂贵业务，也不依赖不稳定外部系统。
  • 压测包含 keep-alive、慢客户端、大响应和 Worker 队列压力，而不只测空 /ping。

4. 性能数据怎么描述

历史 6.5 万 QPS、2–3 ms 只能作为特定硬件、内核、连接方式和业务逻辑下的测试结果。公开材料应同时说明环境与方法，不应承诺任意机器、任意处理器都能达到相同数字。

5. 下一步查什么

指导手册负责建立正确模型。需要完整构造参数、成员函数和错误码时，进入 中文 API 参考；需要复制完整程序时，进入 注释 Demo。
