第 15 章：编码、加密、随机数与解析工具

所有便利函数都有边界：编码不等于加密，伪随机不等于安全随机，低层解析不等于完整协议解析器。

1. Base64 的契约

EncodingUtil::base64_encode() 接受任意二进制字节。base64_decode() 只接受长度、字符和补位合法的无换行 Base64；非法输入返回空字符串。空输入也返回空字符串，因此需要区分时应先检查输入是否为空。

Base64 不是加密。任何人都能还原数据，不能用于隐藏密码、Token 或密钥。

2. SHA-1 与 AES-256-CBC

API输出/行为边界
sha1()20 字节原始摘要协议兼容用途；不用于密码或新签名设计
sha11()40 字符十六进制摘要可读格式不增加安全性
encryptSymmetric(...,outputLength)AES-256-CBC，并返回实际密文长度输出缓冲区至少为明文长度 + EVP_MAX_BLOCK_LENGTH
decryptSymmetric(...,outputLength)验证填充并返回实际明文长度结果是二进制字节，不自动补 \0

旧的无 outputLength 重载为兼容而保留，但新代码应使用带长度的重载。CBC 不提供完整性认证，优先使用 TLS；自行存储密文时还需要 MAC 或 AEAD 方案。

3. 随机字符串

RandomUtil::getRandomStr_base64(str,n) 返回长度严格为 n 的 Base64 字符集伪随机文本。它不带 = 补位，也不保证能作为 Base64 解码，因为它不是“随机字节再编码”。它适合展示 ID、测试数据和采样，不适合作为安全 Token、密钥或 IV。

4. 数字、精度和字节序

  • NumberStringConvertUtil 要求整个输入都合法；8080abc 会失败并写入回退值。
  • toBool() 只有 true/True/TRUE 返回 true，其余内容返回 false；它没有独立失败状态。
  • PrecisionUtil 有格式化字符串和原地修改数值两类接口。金额与精确账务不要使用二进制浮点。
  • NetworkOrderUtil::htonl_ntohl_64() 按当前 Linux 64 位 unsigned long 交换 8 字节；新协议更适合明确使用 uint64_t。

5. HTTP、Query 与位工具

工具已经保证没有保证
HttpStringUtil::get_value_headerHeader 名不区分大小写，并跳过冒号后的空格/Tab不是完整 HTTP parser
get_value_str按 & 字段边界匹配键，id 不会误匹配 userid不执行 URL decode，也不区分“无值”和“未找到”的空结果
WebsocketStringUtil计算 RFC 6455 Accept 值业务层通常不需要手动调用
BitUtil拒绝超长、非 01 位串和非法位位置失败时多使用 0/空结果，没有统一错误对象
注意 string_view 生命周期。HttpStringUtil 的 string_view 重载返回的是原输入字符串中的非拥有视图；原字符串被销毁、重新分配或修改后，视图不能继续使用。需要长期保存时应立即复制为 std::string。

服务端回调优先使用框架已经解析好的 HttpRequestInformation；这些低层工具主要用于受控字符串和协议实现。
