第 15 章：编码、加密、随机数与数据转换

讲清 Base64、SHA-1、AES-CBC、随机数、数值转换和字节序的真实边界。

1. 编码不是加密

EncodingUtil::base64_encode/decode 只改变表示形式，没有保密性。Base64 适合把二进制放进文本协议，不适合隐藏密码或 Token。

2. 哈希与对称加密

API真实用途安全边界
CryptoUtil::sha120 字节二进制 SHA-1协议兼容，例如 WebSocket；不用于密码和新签名设计
CryptoUtil::sha1140 字符十六进制 SHA-1可读校验值，不等于安全密码哈希
encryptSymmetric/decryptSymmetricAES-256-CBCCBC 不提供完整性；密文应配合认证，网络传输优先 TLS
const std::string text = "hello";
const std::string encoded = stt::data::EncodingUtil::base64_encode(text);

std::string digest;
// 输出 40 个十六进制字符；仅用于兼容或普通校验。
stt::data::CryptoUtil::sha11(text, digest);
不要把 SHA-1 当密码哈希。密码应使用 Argon2、scrypt、bcrypt 或 PBKDF2，并使用独立随机盐。不要把固定 IV 的 AES-CBC 当成完整的安全存储方案。

3. 随机数工具

RandomUtil 使用 C++ 随机引擎，适合测试数据、普通 ID、采样和协议掩码；安全令牌、密钥、IV 应使用 OpenSSL RAND_bytes() 或操作系统 CSPRNG。

4. 数值与字符串

  • NumberStringConvertUtil 不抛异常，失败时写入调用者指定的回退值；必须选择不会和合法值混淆的回退值。
  • PrecisionUtil 有“返回格式化字符串”和“直接修改数值”两类重载。金额不要用二进制浮点做最终账务表示。
  • NetworkOrderUtil::htonl_ntohl_64 在 Linux 64 位 unsigned long 上交换 8 字节；跨平台协议更建议使用固定宽度 uint64_t 并明确大小端。
  • HttpStringUtil 是低层字符串辅助工具。服务端已经解析出的请求优先使用 HttpRequestInformation，不要重新解析完整 HTTP 文本。

5. 协议字符串与位工具

工具用途建议
HttpStringUtil提取 URL、路径、Query、Header 和拼接 Header适合受控输入和协议内部；不做 URL decode，部分方法区分大小写
WebsocketStringUtil计算 WebSocket 握手 Accept一般交给 WebSocketServer；业务代码无需手动调用
BitUtil位串显示、位提取和数值转换属于底层二进制/协议工具，注意输入长度和有符号 char
业务层建议：HTTP 服务端读取 Header 时优先用 request.headerValue()；解析完整 URI、百分号编码或复杂 Query 时使用经过验证的 URI 解析器。
