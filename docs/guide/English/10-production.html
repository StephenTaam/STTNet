Chapter 20: Integration and Production Checklist

Turn runnable demos into a bounded, observable service that shuts down safely and can be rolled back.

1. Build and dependencies

Integrate through the CMake target STTNet::sttnet instead of copying individual source files. Use a Release build for deployment and keep separate Debug/ASan builds for regression testing.

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
  • Verify JsonCpp, OpenSSL, pthread, and other runtime dependencies.
  • Do not hard-code development paths for certificates, keys, logs, or configuration.
  • Run protocol interoperability and application regression tests before upgrading STTNet.

2. Network and operating-system resources

Framework capacity settings do not modify Linux limits. Check at least:

AreaWhat to verify
File descriptorsulimit -n, systemd LimitNOFILE, and expected connections
Listen queuelisten_backlog and kernel somaxconn
Write backpressurePer-connection pending bytes, write budget, and slow-client policy
WorkerPoolThread count, pending-task limit, and database/RPC timeouts
HTTP inputHeader, body, upload, and business-field size limits
TLSCertificate expiry, key permissions, protocol versions, and mTLS policy

Related chapters: Server Settings and Security and Input Boundaries.

3. Data, logging, and secrets

  • Return a clear 4xx response when JSON parsing fails; never continue with missing fields.
  • Monitor dropped asynchronous log entries and keep the logger alive through shutdown.
  • Do not log passwords, tokens, cookies, private keys, or complete request bodies by default.
  • Base64 is encoding, not encryption; review the limits of SHA-1 and AES-CBC.
  • Validate size, format, and authorization before external input reaches workers or business code.

Related chapters: JSON, Files and Logging, and Encoding and Crypto Utilities.

4. Process lifecycle

  1. Block SIGINT (2) and SIGTERM (15) before creating threads.
  2. Create the logger, server, Reactor, and workers.
  3. Start listening and expose health/metrics endpoints.
  4. On termination, stop accepting and drain in-flight work and pending writes.
  5. Finish within the shutdown timeout; an external supervisor should use SIGKILL (9) only as the final fallback.

Process provides process launch and restart, not complete Unix daemonization. Prefer systemd, containers, or a dedicated supervisor in production. Related chapters: Linux Signals and Process Supervision.

5. Pre-release checklist

Release principle: Load-test the slowest realistic business path before focusing on empty-response QPS. Capacity is determined by business logic, downstream dependencies, and tail latency.
