Chapter 14: Files and Asynchronous Logging

Move from simple filesystem operations to thread-safe transactions and bounded async logging.

1. Three levels of file support

ClassResponsibilityNote
FileToolCreate/copy paths and query sizeOne-shot filesystem operations
FileThread-safe text/binary operations and memory transactionsCall openFile() first
LogFileBounded queue plus dedicated logging threadDrops records on overload instead of blocking producers

2. Text file example

stt::file::File config;
if(!config.openFile("runtime/app.conf"))
    return 1;

config.deleteAll();
config.appendLine("port=8080");
config.appendLine("workers=4");

std::string content;
config.readAll(content);
config.closeFile();

Methods ending in C operate inside a transaction started by lockMemory(). Use the ordinary methods for single operations, and memory transactions only for multi-step edits. The same thread must unlock the transaction.

3. Asynchronous logging

LogFile log(16384); // Capacity must be a power of two.
if(!log.openFile("logs/server.log", "yyyy-mm-ddThh:mi:ss.sss", "  "))
    return 1;

log.writeLog("server started");
std::cout << log.getDroppedLogCount() << std::endl;

4. Lifetime and performance

  • Keep LogFile alive until all producer threads have stopped.
  • Do not open and close a log file per request.
  • Control hot-path log volume and formatting cost.
  • Never log passwords, complete tokens, cookies, private keys, or sensitive bodies.
  • Queued records can be lost on a hard crash; critical audit trails need a stronger channel.
